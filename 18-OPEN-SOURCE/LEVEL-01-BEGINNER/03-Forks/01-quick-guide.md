# Understanding Forks

## 1. What is it?
Forks are duplicate copies of repositories created inside your own GitHub profile, allowing safe modifications.

## 2. Why do we use it?
To duplicate public repositories into your own profile, enabling you to safely test changes without modifying the original codebase directly.

## 3. How does it work?
- **Analogy**: Photocopying a cookbook. You copy pages, edit recipe details on your page copy, without modifying the library's cookbook.
- **Mechanism**: The feature parses inputs or operations synchronously or asynchronously, executing compiled instructions and returning output responses or state modifications.

## 4. Where is it used?
Open-source contributions and team branches workflows.

## 5. How do we build with it?
```sh
Clicking 'Fork' on GitHub to copy the Express repository to your account, then cloning it locally.
```

- **Expected Output**: Allows safe, isolated development on third-party codebases.
- **Best Practice / Rule**: Forks remain connected to the upstream repository, allowing pull requests later.
