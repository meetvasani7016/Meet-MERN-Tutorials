# Problem Solving Process

## 1. What is it?
Solve programming problems systematically: understand inputs, plan logic, write code, and optimize.

## 2. Why do we use it?
To break complex software requirements down into inputs, pseudocode logic steps, and iterative optimization targets before typing code.

## 3. How does it work?
- **Analogy**: Solving puzzles. You do not just throw pieces together; you sort borders, group colors, and align segments.
- **Mechanism**: The feature parses inputs or operations synchronously or asynchronously, executing compiled instructions and returning output responses or state modifications.

## 4. Where is it used?
Tackling complex backend features or coding challenges.

## 5. How do we build with it?
```json
Breaking a complex database search filter query into simple steps before writing routes.
```

- **Expected Output**: Enables you to tackle complex technical challenges systematically.
- **Best Practice / Rule**: Do not write code until you fully understand the problem! Outline your logic in pseudocode first.
