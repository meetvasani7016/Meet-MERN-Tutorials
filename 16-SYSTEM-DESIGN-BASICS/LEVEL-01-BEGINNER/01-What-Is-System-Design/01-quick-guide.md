# What is System Design

## 1. What is it?
System Design is the process of defining the architecture, components, and data interfaces of an application to satisfy business requirements.

## 2. Why do we use it?
To plan structural designs that handle scale, keep low latencies, and prevent server crashes before writing code.

## 3. How does it work?
- **Analogy**: Architect blueprints. Instead of just laying bricks (coding loops), system design maps out the blueprints of the whole housing complex (servers, databases, caches).
- **Mechanism**: The feature parses inputs or operations synchronously or asynchronously, executing compiled instructions and returning output responses or state modifications.

## 4. Where is it used?
Planning web software architectures and services layouts.

## 5. How do we build with it?
```js
Planning out if an application needs a relational database (SQL) or document storage (NoSQL).
```

- **Expected Output**: Allows teams to build scalable, organized, and reliable software services.
- **Best Practice / Rule**: System design focuses on structural layout and scaling, not syntax optimization.
