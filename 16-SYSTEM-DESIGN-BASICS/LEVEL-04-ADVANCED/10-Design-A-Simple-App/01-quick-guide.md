# Design a Simple App

## 1. What is it?
Apply basic system design principles to plan a simple, scalable web application architecture.

## 2. Why do we use it?
To apply architectural scaling components, data modeling, caching, and load balancing rules to formulate a complete system blueprint.

## 3. How does it work?
- **Analogy**: Combining client interfaces, API servers, cache databases, and persistence servers into a unified blueprint.
- **Mechanism**: The feature parses inputs or operations synchronously or asynchronously, executing compiled instructions and returning output responses or state modifications.

## 4. Where is it used?
System design interviews and architectural planning boards.

## 5. How do we build with it?
```js
Designing a simple collaborative real-time note-sharing board app.
```

- **Expected Output**: Prepares you to map full-stack application blueprints.
- **Best Practice / Rule**: Always start with requirements (user counts, write/read ratios) before selecting databases and load balancers.
